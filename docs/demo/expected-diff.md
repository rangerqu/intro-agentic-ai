# 现场演示参考核对表

只把 `policy-v1.md` 与 `policy-v2.md` 作为模型输入。本文件供讲者验收使用，不作为输入提供给模型。所有内容均为虚构。

| 原文位置 | 旧版 | 新版 | 变化 | 待确认事项 |
|---|---|---|---|---|
| 文首元数据 | 版本 V1；发布 2026-08-01；生效 2026-08-10 | 版本 V2；发布 2026-09-01；生效 2026-09-15 | 版本、发布日期和生效日期变化 | 仅凭这两份文件，不能确认两版之间是否另有过渡安排 |
| 两版第 2 条 | “周三 17:00 前” | “周二 17:00 前” | 常规报送截止时间提前一天，提交目录要求未变 | 无需补写调整原因 |
| V2 第 3 条 | 没有相应条款 | “临时议题可经会议负责人确认后补充提交。” | 新增临时议题路径 | 未明确临时议题的最晚提交时间、确认形式 |
| V1 第 3 条与 V2 第 4 条 | “文件名应包含会议日期、议题名称和版本号。” | 同一句话 | 条号移动，正文要求不变 | 不应把条号移动误报为实质要求变化 |
| 附件第 4 项 | 没有此项 | “上次行动项进展。” | 新增材料要求 | 没有写明统一模板或负责人，不能自行补写 |

第 1 条适用范围、附件前 3 项以及文末演示声明均未变化。

检查重点是完整覆盖正文、附件和元数据，区分新增、实质修改与条号移动。不同措辞均可接受，不要求模型逐字复现本表。

可以现场追问：“临时议题最晚几点提交？”正确处理应指出输入没有明确规定，并建议向相应负责人确认，不能补写一个时间。

若现场工具不可用，打开输入文件与本表进行人工对照，也可以完成讲解。
